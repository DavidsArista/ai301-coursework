# Rubric: is this a good first issue?

## Checks

Use the snapshot capture date for eval recency and today's date for live recency. Read the complete issue and comment thread before grading. Labels and star counts alone never establish a pass. Apply the live scope's classroom house rule only in live mode.

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Human maintenance | Repo-facts last 5 default-branch commits and maintainer first-response sample; issue body and dated OWNER/MEMBER/COLLABORATOR comments. In live mode inspect those same commit and issue surfaces. | At least one of: a human-authored default-branch commit or a bot merge of a human PR within 90 days; an OWNER/MEMBER/COLLABORATOR issue opening or comment within 90 days; or at least 2 sampled issues with maintainer first responses within 30 days. Bot-only dependency updates do not satisfy the commit condition. | required |
| Active project | Repo-facts archived flag, latest release date, and last push date; in live mode repository metadata and Releases. | Repository is not archived, and has either a release within 365 days or a push within 90 days. Stars do not substitute for either activity signal. | required |
| Bounded contribution | Issue body, full comment thread, maintainer scope statements, opening date, and closed-unmerged PR history. | The request identifies one concrete code, test, or documentation outcome. Fail an umbrella of independent tasks, pure usage/support question, unresolved competing designs, explicit maintainer warning that core parser/compiler/architecture changes are needed, or an issue older than 2 years with at least 2 abandoned implementation PRs. A concise description, missing reproduction steps, or absent good-first-issue label is not by itself a failure. A local behavior change with supporting tests is one outcome. A list of related missing cases in one existing feature also counts as one outcome; a short maintainer-authored request naming those cases is sufficient unless the thread supplies a concrete scope blocker. Do not infer an umbrella solely from several examples or the word etc. | required |
| Available work | Repo-facts assignees and linked PR states; entire comment thread for claims, assignments, PR references, and release of claims. In live mode also inspect the Development sidebar and referenced PR states. | Issue is open, has no current assignee, no open implementation PR, and no unresolved claim or progress update within the past 90 days. A later explicit withdrawal or maintainer reopening to contributors clears a claim. A claim older than 90 days with no newer progress, no assignee, and no open implementation PR is stale and does not block work; an open PR or current assignment blocks regardless of age. A PR reference in the thread must be considered even if absent from the sidebar. A closed unmerged PR is not an active claim; a merged fix requires explicit evidence of remaining work. Apply Path Review's exception for other students' claim comments in live mode only. | required |
| Compatible contribution policy | Repo-facts contribution-policy line; in live mode CONTRIBUTING.md, linked contributor/AI policies, and PR templates. | No policy explicitly prohibits the intended AI-assisted contribution workflow. Requirements to disclose AI use, understand changes, test, or review output pass and must be followed. A ban on fully AI-generated submissions alone does not ban assistive use when the policy expressly allows it. Explicit silence on AI/tooling passes; an unread or unavailable policy is unclear. | required |
| Verification guidance | Issue body and comments for expected behavior, a reproduction, named test, or concrete documentation acceptance criteria. | At least one concrete way to verify the requested outcome is supplied, such as an input and expected result, a named relevant test, or an exact documentation correction. | preferred |

## Verdict rule

Accept if and only if every required check passes. A required fail or unclear rejects the issue. Use unclear only when evidence needed to decide is missing, not when a known condition fails. Preferred checks never change the verdict; use their passes to rank accepted issues, together with the live fit profile. Quote the deciding evidence for every grade. Do not infer a student's experience from the rubric.

# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | Compare every file and behavior in Candidate PR Diff with Plan context's scope, files, exclusions, and Deviations; compare PR description's scope claims with both. | Every material change and promised plan outcome appears in the diff, or a concrete deviation is recorded in the plan AND disclosed in the description. No unannounced extra feature, omitted planned outcome, or false "exactly as planned" claim. An honestly disclosed bounded shortfall may pass. | required |
| Description truth | Compare Candidate PR title, Summary, Changes, and Testing claims with the complete Diff, Plan context, and Test evidence. | No material claim is directly contradicted by a visible hunk, test result, or plan boundary. Do not infer that an existing test or formatting check is absent merely because a unified diff shows only changed lines; a named test/check with a reported outcome suffices unless direct evidence disproves it. A claim that a missing planned feature was delivered fails. | required |
| Decisive test evidence | Compare Plan context's reproduction and test plan with Candidate PR Test evidence and any tests added in Diff; read applicable repository-check asks in Repo facts. | The failing issue-specific path (or equivalent regression) has an observable before/after result that would distinguish fixed from unchanged. Each applicable named repository check is reported with its command or check name and outcome, or an honest reason it could not run; a full transcript is valuable but not required for every ancillary check. A passing unchanged control or generic "works" statement alone fails. | required |
| Reviewable diff | Inspect the entire Candidate PR Diff and commit list, including all hunks not highlighted in the description. | The change is focused and inspectable: no debug output, dead or commented-out experiments, unrelated behavior, bulk formatting/import churn, or other debris that obscures the fix. Commit names are supporting context, not a substitute for reading the diff. | required |
| Repository standards | Compare Candidate PR description, issue thread, Repo facts' PR template and contribution/AI policies. | Applicable required template sections and issue linkage contain real content; explicit maintainer requests and contribution rules are met or honestly explained. In eval mode all packages are AI-assisted. Require a tool name and extent only when the stated policy asks for them; a policy asking merely for human-authored comments is met by a comment that says it is in the contributor's own words unless contradicted. Do not invent a policy where none is stated. | required |

## Verdict rule

Grade every row `pass`, `fail`, or `unclear`, with one deciding fact per row. Missing evidence or an unresolvable comparison is `unclear` and counts as failure for a required row. Return `accept` only if every required row passes; otherwise return `reject`. There is no third verdict and no score. An honest shortfall passes only when the plan's Deviations and the PR description disclose it, the implemented slice remains reviewable, and the tests prove that slice.
